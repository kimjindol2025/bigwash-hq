## 1. 합의된 목표 흐름

```text
전화 → 번호·상호 검색/저장 → 상담 메모
 → 출장 | 제품(몰·택배)
 → (출장) 증상·현장힌트 메모 → 직원 배정 → 직원별 스케줄(빈칸) → 직원 승인/반려
 → 직원앱 기본정보(목록 요약 / 클릭 상세)
 → 현장 상담 → 몰 클릭 장바구니(=견적) → PDF·이미지 → 고객 공유(문자·카톡 등은 나중)
 → 순서 여유(견적↔수리↔사진)
 → 전·후 사진 · 결제 중요
 → 완료 선언 가능(미수여도) · 미수는 꼬리표·지속 관리
 → 현장 수금 ↔ 본사 입금확인 동기화
```

고객 앱·고객 완료 버튼은 **보류(고민 중)**. 고객에게 완료를 누르려면 정보·채널이 필요해서 당장 범위 밖.

## 2. 대화에서 고정한 운영 규칙

| 주제 | 합의 |
|------|------|
| 고객 검색 | **전화번호가 기준**, 상호도 포함 |
| 상담만 | **(상담완료)** — 메모·대화 내용 저장. 출장 티켓 없음 |
| 제품 갈래 | 상담 중 사내몰로 제품·금액 확인 → 확정 후 **택배**. 출장과 다른 줄 |
| 원인/증상 | 상담 후 확인. **간단·상세 메모**(예: 허리 아픔 + 허리보호대 준비). 배정 전 강제 잠금 아님 |
| 스케줄 | 직원마다 스케줄러. 본사가 빈 칸에 배정. 직원 **승인 / 반려 / 재승인 요청** |
| 직원 정보 | 배정 시 기본정보 표시. 목록 요약 · 클릭 시 자세히 |
| 출장비 | 가능하면 본사↔출장지(주소) **자동**. 안 되면 직원이 몰에서 클릭. 나중에 문제 되기 쉬움 → 대충 고정 금지 |
| 견적 | **현장 즉시** 대응. 장바구니=견적. 「견적서 작성」→ 본사 전달. 현장은 파일·이미지. 문자·카톡 전달은 연동 후 |
| 순서 | 견적↔수리↔사진 **강제하지 않음**(여유) |
| 완료 vs 미수 | **완료 선언 가능**. 미수가 문제 → 지속 관리. 직원에게 책임감(꼬리표) |
| 꼬리표 | 출장지 · 작업내용 · 금액 · 정산완료\|미수 — 직원에도 필요 |
| 미수 UI | 지난 AS 기록과 **별도** 미수금 카드/탭 |
| 미수 처리 | 현장 수금 → 본사 확인, 꼬리표 유지. 본사 입금은 현장이 모름 → 본사 완료/미수해소 시 **직원 동기화** |
| 고객 앱 | 개발 여부 미정 |

| # | 업무 칸 | 지금 앱 | 중간 UI 제안 | 없음·다음 지시서 |
|---|--------|---------|--------------|------------------|
| 1 | 전화 → 번호·상호 검색/저장 | 전화 데스크, 번호·상호 검색, 신규 저장, 대표전화 중복 방지 | 검색창 라벨 「전화번호(기준) · 상호」 | CTI·자동 팝업 |
| 2 | 상담만 → (상담완료) | 「상담종결」+ 콜/메모 | 버튼 문구 **「상담완료」**, 메모 힌트 | 녹음·자동 전사 |
| 3 | 출장 / 제품 분리 | 출장 티켓 · 구매확정(`ship` 등) | 전화 데스크 **출장 \| 제품(택배)** 두 갈래 카드 | 한 통화 출장+제품 원클릭 묶음 |
| 4 | 증상·현장힌트 메모 | 증상·방문메모 필드 | **간단 / 상세(현장준비)** 두 칸 | 배정 전 원인 강제(불필요) |

## 4. 이미 도는 축 vs 구멍

**이미 도는 축**

전화 데스크 → 고객·상담 → 출장/구매 분리 → 배정·일정(단순) → 현장 상세·몰·장바구니·견적 문서·사진 → 완료·정산 뱃지·본사 사후함(재고장·사진미비·완료미수).

**구멍 (다음 빌더 지시서 후보)**

1. 직원별 스케줄러 + 승인/반려/재요청  
2. 주소 기반 출장비 자동 (+ 실패 시 몰 클릭)  
3. 견적 작성 → 본사 알림/뱃지 강화, 고객 문자·카톡 연동  
4. 직원앱 미수 전용 카드 + 꼬리표 + 본사 입금확인 동기화  
5. 상담완료·간단/상세 메모 UI 다듬기  
6. 고객 앱 (미정)

## 5. 중간 UI 우선순위

### 5.1 잠금 안에서도 가능한 것 (카피·문서·가벼운 라벨)

기능 추가 없이 맞출 수 있는 것:

- 상담종결 → **상담완료** 문구  
- 검색 안내: 전화번호 기준 · 상호 포함  
- 증상 + 현장준비 메모 플레이스홀더 힌트  

(실제 문구 변경도 “기능”으로 보면 지시서에 넣는 편이 안전. 잠금 해석은 사용자·지시서 따름.)

### 5.2 다음 지시서에서 UI + API가 필요한 것

1. 본사 **직원 스케줄 보드** + 직원 **승인/반려**  
2. 직원앱: `오늘 | 예정 | 미수` (또는 미수 카드 분리)  
3. 공통 **꼬리표** 컴포넌트 (출장지 · 작업 · 금액 · 정산)  
4. 본사 **입금확인/미수해소** → 직원 동기  
5. (여유) 견적서 작성 클릭 시 본사 알림

## 6. 현장(tech)과의 경계

- 본사 레포에 직원 UI를 넣지 않는다. 미수 카드·승인 UI는 **bigwash-tech**.  
- HQ API로 상태·정산·문서를 공유하고, 화면은 현장 앱만 담당.  
- 포트: 본사 `30000–39999`, 현장 `40000–49999`.
