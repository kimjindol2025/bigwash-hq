# 본사 세차장 CRM + AS 기획

**범위:** 기획 정본 (앱 본문 구현은 별도 지시 후에만)  
**대상:** 본사 운영툴 (일반 소비자 앱 아님)  
**1단계 채널:** 본사 PC 웹  
**검수:** 조건부 통과 — 고정값은 [`HQ-CRM-AS-REVIEW.md`](HQ-CRM-AS-REVIEW.md)  
**착수 전 5문항:** [`OPEN-DECISIONS.md`](OPEN-DECISIONS.md)  
**빌더 한 장:** [`BUILDER-HANDOFF.md`](BUILDER-HANDOFF.md)  
**DoD:** [`ACCEPTANCE-TESTS.md`](ACCEPTANCE-TESTS.md)

### 제품 정의 (잠금)

> 단일 테넌트부터 켜는 본사 운영 SaaS.  
> 사용자 = 회사 직원.  
> 핵심 객체 = 회사 / 조직 / 직원 / 고객 / 장비 / 티켓.  
> B2C 앱 아님. 스키마는 멀티테넌트(`company_id`), 1차 배포 테넌트 1개 가능.

---

## 1. 한 줄 정의

본사 상담원이 **전화를 받고 → 고객·장비를 찾고 → AS를 접수하고 → 기사 스케줄을 잡고 → 수리·사후처리·전후 사진을 한 건에서 끝까지 보는** 내부 업무 시스템.

---

## 2. 누가 쓰나

| 역할 | 하는 일 |
|---|---|
| 상담/접수 | 전화 수신, 고객 확인, AS 티켓 생성 |
| 배차/스케줄 담당 | 기사 배정, 방문 일정, 일정 충돌 조정 |
| 현장 기사 | (1차는 본사 대행 입력) 출동, 조치, 전후 사진 |
| 본사 관리자 | 고객·장비 마스터, 상태 모니터링, 미처리 독촉 |
| 대표/팀장 | 대시보드만 본다 (미처리, 지연, 재고장) |

1단계 = **본사 PC 웹만**. 기사 모바일 = 2단계.

---

## 3. 핵심 업무 흐름

```
전화 수신
  → 고객 검색 (없으면 신규)
  → 설치 장비 선택 (장비명 + 시리얼/위치)
  → 고장 증상 등록
  → AS 티켓 생성 (접수)
  → 희망일/긴급도 확인
  → 기사·방문슬롯 배정
  → 출동 / 수리 / 보류(부품대기)
  → 전후 사진 3~5장
  → 조치내용·사용부품·비용
  → 완료
  → 사후확인 (통화/재방문/무상보증)
```

한 티켓 화면에서 **접수 ~ 사후확인**이 타임라인으로 보여야 한다.  
엑셀·카톡 병행이면 실패.

---

## 4. 화면 구성 (정보구조)

1. **로그인 / 지점·권한** — 본사 전용. 나중에 지점 조회만 열 여지.
2. **대시보드** — 오늘 전화 / 오늘 방문 / 미배정 / 지연 / 부품대기 / 오늘 완료 / 재고장(30·90일) / 긴급 티켓
3. **전화 접수** — 번호 자동검색, 최근 AS·보유장비, “이 전화로 새 AS”, 통화메모, 상담유형(AS/예약문의/클레임/부품/기타)
4. **고객 CRM** — 유형(가맹/개인매장/직영/기타), 상호·담당자·전화·주소·영업시간·주차·출입, 계약/보증, 보유장비·AS이력·통화이력
5. **장비 마스터** — 장비명·모델·시리얼·설치일·보증만료·설치위치·사진·고장 이력
6. **AS 티켓 (핵심)** — 고객+장비+증상, 상태 파이프라인, 배정/방문, 조치·부품·비용, 전후 사진, 사후, 타임라인
7. **스케줄** — 1단계 목록+배정, 충돌 경고. 드래그 캘린더는 2단계
8. **사후처리함** — 완료 후 N일 미확인, 재고장 의심, 불만 재오픈
9. **설정** — 기사, 고장유형, 상태값, 보증일수, 알림기준

---

## 5. AS 상태 파이프라인

`접수 → 배정대기 → 배정됨 → 출동중 → 수리중 → 부품대기 → 완료 → 사후확인 → 종결`

예외: `보류`, `취소`, `재오픈`

필터: 상태 · 기사 · 권역 · 긴급도 · 지연여부

---

## 6. AS 등록 필수 항목

### 접수 시
- 고객
- 장비 이름/모델 (필수). 시리얼은 있으면
- 고장 유형 + 증상 서술
- 발생시점, 긴급도(일반/당일/긴급)
- 희망 방문일시
- 상담원 메모, 수신번호

### 처리 중
- 기사, 방문슬롯
- 현장 원인, 조치내용
- 부품(있으면)
- 유상/무상, 견적·청구(단순 금액부터)

### 완료·사후
- 전 사진 3~5, 후 사진 3~5
- 고객 확인(통화일시, 만족/불만)
- 보증 잔여, 재방문 필요 여부

사진: 1단계는 **슬롯 설계**. BEFORE 1~5 / AFTER 1~5.  
미첨부 완료 시 경고(강제 여부는 설정).

## 7. 기획에 반드시 넣는 구멍 메움

- **고객-장비 1:N**
- **재고장 자동표시** (같은 장비 30일 이내 재접수)
- **보증 판정 힌트** (설치일·보증만료 → 무상/유상)
- **통화 로그** (티켓·고객 양쪽에 연결)
- **미배정·지연 SLA** (예: 긴급 2h 미배정, 일반 24h 미방문)
- **권역/기사 숙련** — 1차는 수기 배정
- **부품 대기** — 상태만 (재고는 3단계)
- **권한** — 상담/배차/관리자
- **검색** — 전화, 상호, 장비명, 시리얼, 티켓번호
- **데이터** — 실사용은 서버+백업 (데모용 브라우저 저장만으로는 불가)

### 1단계 밖 (넣지 않음)
고객앱·카톡 챗봇, 결제·세금계산서, GPS 관제, AI 진단, 재고 ERP

## 10. 성공 기준

- 상담원이 전화 중 **90초 안**에 고객+장비+신규 AS
- 관리자가 **미배정·지연·부품대기**를 대시보드에서만 본다
- 한 티켓에 **증상 → 조치 → 사진 → 사후**가 한 스크롤
- 같은 장비 재접수가 숨지 않는다

---

## 11. 리스크

- 장비 마스터 공백 → AS가 장비명 텍스트로  degenerate → 초기 장비 등록 캠페인 필요
- 사진 용량·개인정보(번호판/얼굴) → 저장 정책
- 카톡/메모장 병행 → 접수 창구를 여기로만

## 12. 현재 코드베이스와의 관계

이 문서가 **제품 정본**이며, 앱 본문 재작성은 **명시 지시 후**에만 한다.
