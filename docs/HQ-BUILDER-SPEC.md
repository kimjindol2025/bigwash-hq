# 빌더 지시서 — bigwash-hq (정본)

대상 저장소: `https://github.com/kimjindol2025/bigwash-hq`  
브랜치: `main`  
역할: 본사 앱만 완성한다. 기획 검수자는 코드 안 짠다.

이 문서가 `docs/HQ-BUILDER-SPEC.md`를 **대체**한다. 대화 원문·옛 REVIEW·OPEN-DECISIONS·README의 고객포털 설명보다 **이 문서가 위**다.

---

## 0. 제품

본사 운영 SaaS. 전화가 입구. 고객 앱 없음.

```
전화 → 고객 CRM → (기본) 출장
 → 직원 1..N 지정(용병은 본사만 기록)
 → 권역 출장비 + 사내몰 부품 N
 → 견적/명세(PDF·이미지)
 → 직원앱은 다른 저장소/나중에
 → 본사는 사진·일지·완료·정산버튼 수신
 → 내부정산(출장·수리·경비·급여) + 엑셀 보고
```

앱 분리
- **본사 앱** = 이 레포. PC + 모바일(같은 UI, 전화 데스크 포함).
- **직원 앱** = 만들지 말 것. 데이터 필드만 받을 준비.
- **용병** = 계정·앱 없음. 본사 수기.

로그인: 아이디+비밀번호. 전화 로그인 없음.

테넌트: 모든 업무 테이블 `company_id`. 물리 삭제 없음.

## 5. 고객

전화 중 필수: 유형, 표시명, 대표전화, 주소, 상태(거래중/휴면/종료)

권고: 공식상호, 추가전화, 현장담당, 담당자폰, 방문메모, 영업시간, 태그, **권역(region_id)**, 본사고객담당, 등급, 정산메모, 보증메모

규칙
- 번호·상호 검색. 본사대표번호 + 직원휴대폰으로 온 번호도 같은 검색창.
- 대표전화 중복 저장 금지.
- 전화·주소 변경 이력.
- 삭제 없음.
- 저장 / 저장 후 출장 / 저장 후 상담종결.

고객에 `region_id` 추가 (현재 스키마 누락).

## 6. 장비

고객 1:N. 필수: 이름, 위치.  
출장 티켓 = 장비 1대 필수. 없으면 그 자리 추가.  
철거는 상태. 삭제 없음.  
주 장비 1대/티켓. 추가는 메모.

---

## 7. 구매확정 · 무상 (신규 필수)

고객 등록 후 본사가 **사내몰 상품을 골라 고객에 붙이고 날짜를 수기**하면 구매확정.

테이블 `hq_customer_purchases`
- company_id, customer_id, product_id
- fulfill_type: `ship` | `install`
- confirm_date (본사 수기) — ship면 발송일, install면 설치일
- equipment_id (설치형이면 연결 권고)
- note

무상 규칙  
**그 고객·그 물품(연결 장비)의 confirm_date + 365일 이내만 무상. 기록 없으면 유상.**  
자동 계산, 본사가 플래그 덮어쓰면 로그.

장비 `warranty_until`만으로 무상 판정하지 말 것.

## 8. 전화 데스크

CTI 없음. 번호 붙여넣기 → 고객 → 장비·최근출장·구매/무상힌트.  
기본 버튼: 출장 만들기. 보조: 상담종결.  
콜 로그 = 고객+티켓.

---

## 9. 티켓 (얇게)

유형 출장(기본) | 상담  
필드: 고객, 장비, 증상, 유형선택, 권역(고객 복사·수정), 방문일시, 업무상태, 정산상태(수신)

업무: 접수 / 배정대기 / 배정됨 / 출장중 / 완료 / 종결  
예외: 보류, 취소(사유), 재오픈  
상담: 접수 → 상담종결

완료 ≠ 정산.

재고장: 같은 equipment_id, 완료 후 30일 이내.

## 10. 배정 · 스케줄

- 직원 **먼저** 고르고 일정 부여.
- **1명 또는 N명.** 주담당 1 + 동행 N.
- 정규 직원 + **용병(일용)**. 용병은 드롭다운에 이름만. 로그인 계정 생성 화면에서 빼거나 종류=용병이면 계정 필드 숨김.
- 휴직·퇴사 정규직 신규지정 불가.
- 겹침 경고만.
- 용병 보수는 **그날 출장일지에 금액 수기** (본사가 씀). 월급 대장에 넣지 않음.

`hq_ticket_assignees` (ticket_id, user_id nullable, contractor_name, kind, is_primary, day_pay_amount)

---

## 11. 권역 출장비

설정 테이블 광역+세부. 단가 본사 편집.  
티켓 권역 → 명세/장바구니에 **출장비 1줄 자동**. 직원이 담지 않음.  
그외 = 수기+사유. 발행 시점 단가 고정.

---

## 12. 사내몰 · 장바구니

상품 마스터: 이름, 카테고리, 규격, 품번, 판매가, 원가(경리), 단위, 판매중, 설명, 이미지선택, **fulfill_type(ship|install|part)**  
재고 없음.

장바구니 (출장 티켓에 묶음)
```
부품 1..N (product_id)
+ 공임 0..1
+ 출장비 1줄 (권역)
```

증정 1+1 넣지 말 것.

견적 저장 → 명세 확정.  
확정 후 본사만 취소·재발행.

구매확정과 출장 장바구니는 **같은 상품 마스터, 다른 테이블.**

## 13. 견적 · 명세 파일

동시 산출: **PDF + 세로 이미지**. text API는 임시, UI에 임시 표시.  
내용: 회사명, 일자, 문서번호, 고객, 장비, 출장일, 담당, 출장비, 공임, 부품라인, 합계, 유상/무상, 메모, **계좌 한 줄**. 도장은 있으면.

본사: 보기·다운로드. 자동 전송 없음. 직원이 공유하는 것은 직원앱 범위.

무상이면 합계 0, 라인 유지.

## 14. 본사가 수신만 하는 현장 값

업무완료: 전 사진 1–5, 후 1–5, 조치, 확정명세, 출장일지  
정산 버튼값 그대로 뱃지:

`카드완납 | 계좌완납 | 현금완납 | 부분수금 | 미수 | 해당없음`

부분수금 = 받은금액+수단.  
무상 합계0 = 해당없음.

완료와 정산 순서 강제 없음.

## 19. 오너 확정 (더 묻지 말 것)

- 회계: 내부 정산만  
- 급여: 기본+수당/공제 수기 (정규직)  
- 출장비: 지역별 단가. 수리비=자재+난이도  
- 출퇴근: 본사 대행+휴무. 직원 타각 없음  
- 완료보고서: 직원앱이 제출. HQ는 수신. 용병은 본사 대행  
- 운영비 항목: 임대·차량·부품·통신·기타  
- 보고: 화면+엑셀  
- 고객: B2B 기본, B2C 유형만 예약  
- 권한: 급여 경리, 경비 신청+승인  
- 돈 4종 전부 1차  
- 고객앱: 없음  
- 전화 기본 결과: 출장  
- 무상: 구매확정 1년  
- 구매: 본사 몰 선택 + 날짜 수기  
- 기점: 택배=발송일, 설치=설치일  
- 명세 계좌 한 줄, 도장 선택  
- 배정 1..N + 용병  
- 용병 보수: 당일 일지 수기  
- 용병 앱: 없음  
- 본사: PC+모바일, 전화데스크 포함  
- 로그인: 아이디+비번  
- 알림 1차: 앱 안만 (문자 없음)

## 20. 수락 테스트 (전부 PASS여야 1차)

기존 §19 10개 유지 + 아래.

11. 고객에 몰 상품 구매확정, 발송일 수기 → 200일 후 출장 무상 힌트, 400일 후 유상.  
12. 설치형 구매 + 설치일 수기 → 기점이 설치일.  
13. 출장에 정규 1 + 용병 1 배정. 용병 로그인 생성 실패 또는 UI 없음. 일지 금액 수기.  
14. 장바구니 부품 2 + 출장비 1줄 = 명세 합계. 출장비는 권역 변경 시 따라감.  
15. 명세 PDF와 이미지 둘 다 다운로드되고 내용이 같음.  
16. 정산=미수 뱃지가 본사 보드·대시보드에 버튼 문구와 같음.  
17. `/register.html`, `/customer.html`, 비인증 접수가 404이거나 레거시 전용.  
18. README 첫 화면이 본사 HQ.  
19. 고객 region 저장 → 새 출장에 복사.  
20. 퇴사 정규직 지정 불가 + 용병 과거 출장 유지.

## 21. 완료 정의

레거시 고객입구가 꺼지고, 구매확정·N배정·용병수기·실파일 명세·권역출장비가 본사 화면에서 한 줄로 이어지면 1차 끝.
